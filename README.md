# git-mcp-agent

MCP-сервер git-инструментов на Rust: модель через любой MCP-клиент смотрит в
git-репозиторий (статус, диффы, лог, коммиты, ветки) и, если клиент
разрешит, пишет в него. Сервер вызывает системный `git`; Python, `uv` и сеть
не нужны. Протокол — JSON-RPC через stdin/stdout (транспорт stdio).

Сервер вынесен из [`agent-cli`](https://github.com/Egor-Liadsky/agent-cli),
где раньше был крейтом `crates/git-mcp` с клиентским префиксом в имени
бинарника; история файлов перенесена вместе с ним. Консольный клиент `agentcli` остаётся одним из клиентов сервера и
связан с ним только процессом — cargo-зависимости между проектами нет.

## Устройство

Cargo workspace (Rust edition 2024) из одного крейта:

| Крейт     | Каталог      | Что это                                  |
|-----------|--------------|------------------------------------------|
| `git-mcp` | `crates/git` | бинарник `git-mcp` — MCP-сервер над `git` |

- `crates/git/src/main.rs` — инструменты, их аргументы и разбор ключа
  `--repository`;
- `crates/git/src/git.rs` — запуск `git -C <репозиторий>` и отказ от
  аргументов, похожих на флаги;
- `crates/git/tests/protocol.rs` — проверка настоящего процесса MCP-клиентом
  `rmcp` на временном репозитории.

| Назначение                 | Крейты                                           |
|----------------------------|--------------------------------------------------|
| MCP-сервер                 | `rmcp` (server, macros, transport-io)            |
| JSON-схемы аргументов      | `schemars`                                       |
| Асинхронный рантайм        | `tokio`                                          |
| Сериализация               | `serde`                                          |
| Обработка ошибок           | `anyhow`                                         |
| Тесты (MCP-клиент)         | `rmcp` (client, transport-child-process), `serde_json` |

## Установка

```bash
cargo install --git https://github.com/Egor-Liadsky/git-mcp-agent git-mcp
```

Из локальной копии (в зонтичном репозитории
[`agent`](https://github.com/Egor-Liadsky/agent) она лежит подмодулем `mcp`):

```bash
cargo install --path crates/git
```

Бинарник попадает в `~/.cargo/bin`. Сборка без установки —
`cargo build --release`, результат в `target/release/git-mcp`.

## Запуск

```bash
git-mcp --repository <путь к git-репозиторию>
# или
git-mcp --repository=<путь>
```

Каталог должен существовать и содержать `.git` (каталог у обычного
репозитория, файл у рабочего дерева `git worktree`). Проверка идёт до
рукопожатия MCP: с неверным путём процесс сразу завершается с ошибкой в
stderr, а не отвечает ошибкой на каждый вызов.

Репозиторий задаётся только ключом `--repository`, один на процесс.
Аргумент `repo_path`, который есть у инструментов
[`mcp-server-git`](https://github.com/modelcontextprotocol/servers/tree/main/src/git),
сервер не объявляет и игнорирует: модель не может обратиться к другому
репозиторию.

Подключение к клиенту с конфигурацией в стиле Claude Desktop:

```json
{
  "mcpServers": {
    "git": {
      "command": "git-mcp",
      "args": ["--repository", "/path/to/repo"]
    }
  }
}
```

`agentcli` находит бинарник сам: переменная окружения `AGENTCLI_GIT_MCP`
(путь к бинарнику), затем каталог рядом с исполняемым `agentcli`, затем
`PATH` — подробности в README `agent-cli`, раздел «Git-инструменты (MCP)».

## Инструменты

Имена и аргументы совпадают с `mcp-server-git`, чтобы клиент
(классификация читающих и пишущих, подтверждение) не зависел от того, какой
из серверов запущен.

Читающие:

| Инструмент          | Аргументы                                              |
|---------------------|--------------------------------------------------------|
| `git_status`        | —                                                      |
| `git_diff_unstaged` | `context_lines` (по умолчанию 3)                       |
| `git_diff_staged`   | `context_lines` (по умолчанию 3)                       |
| `git_diff`          | `target`, `context_lines` (по умолчанию 3)             |
| `git_log`           | `max_count` (по умолчанию 10), `start_timestamp`, `end_timestamp` |
| `git_show`          | `revision`                                             |
| `git_branch`        | `branch_type` (`local`, `remote`, `all`), `contains`, `not_contains` |

Пишущие:

| Инструмент          | Аргументы                          |
|---------------------|------------------------------------|
| `git_add`           | `files` — пути от корня репозитория |
| `git_commit`        | `message`                          |
| `git_reset`         | — (снимает всё проиндексированное)  |
| `git_create_branch` | `branch_name`, `base_branch`       |
| `git_checkout`      | `branch_name`                      |

Аннотаций вроде `readOnlyHint` сервер не выставляет: спецификация MCP
называет их недоверенными, и решение, что выполнять без подтверждения,
принимает клиент по имени инструмента.

Ошибка `git` (ненулевой код выхода) возвращается результатом-ошибкой
инструмента с текстом stderr, а не ошибкой протокола: модель видит причину
и может исправить вызов. Пустой вывод заменяется пояснением вроде
`(no unstaged changes)`, чтобы модель не приняла пустую строку за сбой.

## Защита аргументов

- Ревизии, ветки и даты, начинающиеся с `-`, отклоняются: `git` прочитал бы
  их как флаги (например `--output=<файл>` у `git diff` записал бы файл вне
  репозитория).
- Пути в `git_add` идут после `--`, а путь за пределами репозитория
  отклоняет сам `git`.
- Сообщение коммита передаётся значением `-m`, поэтому ведущий `-` в нём
  безопасен.
- Ни пейджера, ни редактора, ни запроса пароля (`GIT_PAGER=cat`,
  `GIT_EDITOR=true`, `GIT_TERMINAL_PROMPT=0`, stdin закрыт): stdin у
  сервера занят протоколом, и любой интерактив повесил бы вызов.
- Пути с кириллицей выводятся как есть (`core.quotepath=off`).

## Разработка

```bash
cargo build --release
cargo test
cargo clippy --all-targets -- -D warnings
```

Тесты протокола запускают собранный бинарник (`CARGO_BIN_EXE_git-mcp`) и
создают временные репозитории в системном временном каталоге; нужен
системный `git`.
